============================================================
NOUVEAUTÉS V1.8.0
============================================================

1. PAIEMENT DE CARTE LIÉ

Un nouveau bouton « Paiement de carte » est disponible dans Finances et dans
la Saisie rapide.

Le formulaire permet de choisir :
- le compte bancaire de départ;
- la carte de crédit destinataire;
- le montant;
- la date du débit bancaire;
- la date de réception sur la carte;
- le statut Prévu / Confirmé;
- « Déjà programmé auprès de la banque »;
- un rappel facultatif;
- une note.

Le paiement est automatiquement Hors budget.

Un seul paiement logique produit deux effets liés :
- une sortie dans le compte bancaire;
- un crédit sur la carte de crédit.

Dans l’Historique général, une seule ligne est présentée afin d’éviter un
doublon visuel. Elle indique la relation « Compte → Carte ».

Lorsque le paiement est confirmé, son côté carte apparaît dans Conciliation
comme un paiement reçu/crédit appliqué. Il réduit le solde dû de la carte.

Modifier, confirmer ou supprimer un paiement lié agit sur les deux côtés.
Si un côté est déjà concilié, il faut d’abord retirer cette conciliation.

2. INDICATEUR « PROGRAMMÉ » DANS L’HISTORIQUE

Une transaction prévue dont la case « Programmée dans le compte bancaire »
est cochée affiche maintenant directement le libellé court « Programmé » sur
sa ligne dans l’Historique.

Le même libellé compact est utilisé dans la vue Compte et dans le détail des
transactions à venir lorsque pertinent.

3. TABLEAU — TRANSACTIONS À VENIR REPLIÉES

Les trois montants suivants restent toujours visibles :
- Dépenses à venir;
- Revenus à venir;
- Effet net prévu.

Les listes « Dépenses prévues » et « Revenus prévus » sont repliées par défaut.
Le bouton « Voir les transactions à venir » ouvre le détail au besoin et
indique le nombre de dépenses et de revenus prévus.

Cette modification réduit fortement la hauteur du Tableau, particulièrement
sur téléphone.

4. EXPORTS

Le CSV indique maintenant si un mouvement est un paiement de carte lié ainsi
que son compte de départ et sa carte destinataire.

La sauvegarde JSON contient aussi les données des paiements de cartes liés.

============================================================
INSTALLATION
============================================================

1. Ouvrir le dépôt GitHub JF Apps.
2. Add file > Upload files.
3. Remplacer ensemble :
   - finances.py
   - finances_data.py
   - app_versions.py
   - manual.py
4. Commit changes.
5. Attendre le redéploiement complet de Canner.
6. Vérifier que Finances affiche V1.8.0.
7. Sur ordinateur : Ctrl+F5 si l’ancienne interface reste en cache.
8. Sur téléphone/PWA : fermer complètement JF Apps puis la rouvrir au besoin.

============================================================
TESTS RECOMMANDÉS APRÈS DÉPLOIEMENT
============================================================

A. Démarrage
1. Vérifier que le Portail démarre normalement.
2. Ouvrir Finances et confirmer la version V1.8.0.

B. Paiement de carte lié
1. Vérifier dans Organisation qu’un mode est de type « Compte bancaire » et
   qu’un autre est de type « Carte de crédit ».
2. Saisie > Paiement de carte.
3. Choisir le compte bancaire et la carte.
4. Créer un paiement Prévu de test, par exemple 9,00 $.
5. Cocher « Déjà programmé auprès de la banque ».
6. Vérifier dans Historique :
   - une seule ligne;
   - « Hors budget »;
   - « Programmé »;
   - « Compte → Carte ».
7. Vérifier dans Compte que le paiement réduit le solde bancaire prévu.
8. Confirmer le paiement.
9. Ouvrir Conciliation sur la carte : le paiement doit apparaître comme un
   crédit/paiement reçu et réduire le solde dû.
10. Modifier un paiement non concilié et vérifier que les deux côtés changent.
11. Supprimer un paiement non concilié et vérifier que les deux côtés
    disparaissent.

C. Protection de la conciliation
1. Concilier le côté carte d’un paiement lié.
2. Tenter de modifier ou supprimer le paiement depuis l’Historique.
3. L’application doit demander de retirer d’abord la conciliation.

D. Tableau compact
1. Ouvrir Tableau sur un mois ayant des transactions futures.
2. Vérifier que Dépenses à venir / Revenus à venir / Effet net prévu restent
   visibles.
3. Vérifier que les longues listes sont fermées par défaut.
4. Cliquer « Voir les transactions à venir » et vérifier l’ouverture du détail.

E. Régression V1.7
1. Modifier une récurrence et vérifier le recalcul des occurrences prévues.
2. Vérifier les KPI configurables dans Organisation.
3. Vérifier une Marge de crédit dans Compte.
4. Vérifier Budget ↔ Récurrence et les rappels existants.

============================================================
NOTE DE SÉCURITÉ DES DONNÉES
============================================================

La migration ajoute uniquement les structures nécessaires aux paiements liés.
Elle ne supprime ni ne remplace les transactions existantes.

Comme toujours, une sauvegarde JSON avant un changement important demeure une
bonne pratique.
