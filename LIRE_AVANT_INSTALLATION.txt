NOUVEAUTÉS DE LA V1.3.0

1. SOLDE PRÉVU CUMULATIF
Le Tableau affiche maintenant un solde prévu pour chaque mode de paiement.

Le calcul ne recommence jamais à zéro au changement de mois.

Solde confirmé non concilié =
- ajustement initial non concilié;
- plus les dépenses confirmées non conciliées;
- moins les revenus, remboursements et crédits confirmés non conciliés.

Les transactions prévues sont présentées séparément, puis ajoutées au
solde prévu.

2. NOUVEL ÉCRAN CONCILIATION
Un onglet « Conciliation » est ajouté dans Finances.

Il permet :
- de choisir un mode de paiement;
- d’afficher toutes ses transactions confirmées non conciliées;
- de filtrer par dates;
- de rechercher une transaction;
- de cocher plusieurs transactions;
- de tout sélectionner ou tout désélectionner;
- de voir le total sélectionné;
- de voir le solde non concilié restant;
- de finaliser la sélection en une seule opération.

3. CONCILIATION PAR RELEVÉ
Chaque séance peut conserver :
- la date du relevé;
- le solde du relevé;
- la date de paiement;
- la date réelle de conciliation;
- une note;
- les transactions sélectionnées;
- l’ajustement initial;
- le total concilié;
- la différence avec le relevé.

Une différence non nulle produit un avertissement, mais la conciliation
peut tout de même être enregistrée après confirmation.

4. HISTORIQUE DES CONCILIATIONS
Chaque séance est conservée.

Il est possible :
- de consulter les transactions d’une séance;
- de retirer une transaction d’une séance;
- d’annuler toute une conciliation.

Une transaction retirée ou une séance annulée retourne immédiatement
dans le solde non concilié.

5. AJUSTEMENT INITIAL
Dans Organisation > Modes de paiement, chaque mode peut maintenant
contenir :
- un type;
- un jour habituel de fermeture du relevé;
- un jour habituel de paiement;
- un solde initial ou ajustement;
- une date de référence;
- une note.

L’ajustement initial reste dans le solde prévu jusqu’à son inclusion
dans une séance de conciliation.

6. ATTRIBUTION EN LOT
L’écran Conciliation contient une section « Transactions sans mode de
paiement ».

Plusieurs transactions peuvent être cochées et recevoir le même mode
de paiement en une seule opération.

7. PROTECTION DE L’HISTORIQUE
Une transaction déjà conciliée ne peut plus être modifiée ou supprimée
directement.

Il faut d’abord :
- ouvrir la séance de conciliation;
- retirer la transaction;
- puis la modifier ou la supprimer.

8. EXPORTATION
Le CSV indique maintenant l’identifiant de la séance de conciliation.

Le JSON de sécurité comprend aussi :
- les séances de conciliation;
- les liens entre les séances et les transactions;
- les renseignements détaillés des modes de paiement.

MIGRATIONS POSTGRESQL AUTOMATIQUES
Le démarrage de l’application ajoute automatiquement :
- les nouveaux renseignements des modes de paiement;
- la table finance_reconciliation_sessions;
- la table finance_reconciliation_session_transactions;
- la liaison entre une transaction et sa séance de conciliation.

Aucun script SQL manuel n’est requis.
Les transactions, catégories, étiquettes, objectifs, récurrences,
imports et conciliations existantes sont conservés.

INSTALLATION
1. Ouvrir le dépôt GitHub.
2. Choisir Add file > Upload files.
3. Déposer ensemble :
   - finances.py
   - finances_data.py
   - app_versions.py
   - manual.py
4. Faire Commit changes.
5. Attendre le déploiement Canner.
6. Recharger avec Ctrl+F5 ou fermer et rouvrir la PWA.
7. Vérifier que Finances affiche V1.3.0.

TEST RECOMMANDÉ
1. Ouvrir Organisation > Modes de paiement.
2. Modifier un mode et inscrire un solde initial facultatif.
3. Attribuer un mode à quelques transactions.
4. Ouvrir Tableau et vérifier le solde prévu.
5. Ouvrir Conciliation.
6. Choisir le mode.
7. Cocher quelques transactions.
8. Inscrire une date et un solde de relevé.
9. Finaliser.
10. Vérifier que les transactions ne sont plus dans le solde confirmé.
11. Ouvrir l’historique de la séance.
12. Retirer une transaction et vérifier qu’elle revient dans le solde.
13. Tester l’annulation complète d’une séance.
